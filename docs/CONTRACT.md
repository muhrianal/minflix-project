# SHARED CONTRACT: Mini Netflix (VOD)

> Single copy at `minflix/docs/CONTRACT.md`, shared by minflix-be, minflix-fe and minflix-infra.
> Do NOT change it without telling the user. If the contract must change, stop and ask first.

## System summary
Users register/login, upload a video, wait for it to be transcoded into HLS (adaptive bitrate), then watch it with a quality selector.
- The browser uploads the raw video DIRECTLY to S3-compatible storage via a presigned PUT URL. Video bytes never pass through the API.
- After upload, the browser calls the API. The API enqueues a transcode job. A worker runs FFmpeg, uploads HLS output to storage, and marks the video READY.
- Playback: the browser fetches `master.m3u8` and segments from the URL given by the API, using hls.js.

## Environments
Two environments only: `dev` and `prod`.

| | dev | prod |
|---|---|---|
| Where | docker compose for infra; API/worker from IDE or compose; FE with `npm run dev` | AWS, provisioned by Terraform (minflix-infra) |
| Object storage | MinIO | S3 (private bucket) |
| Queue | RabbitMQ container | Amazon MQ for RabbitMQ |
| Database | MongoDB container | Amazon DocumentDB |
| CDN | none (MinIO anonymous read on `hls/`) | CloudFront |
| Compute | local JVM or containers | ECS Fargate: `api` service behind an ALB, `worker` service |
| Backend config | `application-dev.yml` (Spring profile `dev`) | `application-prod.yml` (Spring profile `prod`) |

The Spring profile `worker` is separate: it switches a process into transcode-worker mode (e.g. `dev,worker` or `prod,worker`).

### Public URLs
- dev: FE http://localhost:5173, API http://localhost:8080, HLS http://localhost:9000/minflix/hls/...
- prod: ONE CloudFront domain `https://<cf-domain>` serves the FE (`/`), the API (`/api/*` -> ALB) and HLS (`/hls/*` -> S3). The FE therefore calls the API with RELATIVE urls in prod. The raw upload still goes browser -> S3 directly on the S3 domain (presigned URL).

### dev ports
API 8080 | Frontend 5173 | MinIO API 9000 (console 9001) | RabbitMQ 5672 (UI 15672) | MongoDB 27017

## Video status lifecycle
UPLOADING -> PROCESSING -> READY (or FAILED). Only the backend changes status.

## API (base path /api, JSON; all endpoints except auth require `Authorization: Bearer <jwt>`)

POST /api/auth/register
  body: { "email": string, "password": string }
  201: { "token": string }
  409: { "message": "Email already registered" }

POST /api/auth/login
  body: { "email": string, "password": string }
  200: { "token": string }
  401: { "message": "Invalid credentials" }

POST /api/videos
  body: { "title": string, "filename": string, "contentType": string }
  201: { "videoId": string, "uploadUrl": string }
  Video is created with status UPLOADING. Client must PUT the raw file to uploadUrl
  with header Content-Type equal to the contentType sent here.

POST /api/videos/{id}/complete
  no body. Owner only (403 otherwise). Sets PROCESSING and enqueues the transcode job.
  200: Video

GET /api/videos
  200: Video[] newest first. All READY videos from everyone, plus the caller's own videos in any status.

GET /api/videos/{id}
  200: Video
  404: { "message": "Not found" }

Video:
  { "id": string, "title": string, "status": "UPLOADING"|"PROCESSING"|"READY"|"FAILED",
    "ownerId": string, "masterPlaylistUrl": string|null, "durationSec": number|null,
    "createdAt": ISO-8601 string }
masterPlaylistUrl is null until status is READY.

Errors: always { "message": string } with a proper status (400, 401, 403, 404, 409).

Operational (not part of the app API, not routed through CloudFront):
  GET /actuator/health  -> 200 {"status":"UP"}, public. Used by the ALB health check.

## Storage layout (one bucket per environment; name comes from config `storage.bucket`)
dev bucket: `minflix`. prod bucket: generated by Terraform.
  raw/{videoId}/original.<ext>          browser upload target (private in both envs)
  hls/{videoId}/master.m3u8
  hls/{videoId}/720p/index.m3u8 + segN.ts
  hls/{videoId}/480p/index.m3u8 + segN.ts
  hls/{videoId}/360p/index.m3u8 + segN.ts
`hls/` is publicly readable: in dev through a MinIO anonymous-download policy, in prod ONLY through CloudFront (the bucket itself stays private). `raw/` is never publicly readable.
Browser PUT to the presigned URL needs bucket CORS (dev: all origins; prod: the CloudFront origin only; methods GET/PUT/HEAD, all headers).

masterPlaylistUrl = `{storage.playlist-base-url}/hls/{videoId}/master.m3u8`
  dev:  http://localhost:9000/minflix/hls/{videoId}/master.m3u8
  prod: https://<cf-domain>/hls/{videoId}/master.m3u8

## Prod runtime configuration (interface between minflix-be and minflix-infra)
Terraform injects these into the ECS tasks (api and worker). `application-prod.yml` reads them with NO defaults, so a missing value fails at startup.

| Env var | Source | Used for |
|---|---|---|
| SPRING_PROFILES_ACTIVE | task definition | `prod` (api) / `prod,worker` (worker) |
| SPRING_MAIN_WEB_APPLICATION_TYPE | task definition, worker only | `none` |
| MONGODB_URI | Secrets Manager | full DocumentDB URI incl. credentials |
| RABBITMQ_HOST | task definition | Amazon MQ broker hostname (amqps, port 5671) |
| RABBITMQ_USERNAME | task definition | broker user |
| RABBITMQ_PASSWORD | Secrets Manager | broker password |
| JWT_SECRET | Secrets Manager | HS256 signing key |
| STORAGE_BUCKET | task definition | S3 bucket name |
| AWS_REGION | task definition | S3 region |
| PUBLIC_BASE_URL | task definition | `https://<cf-domain>`; used for playlist URLs and the CORS allowed origin |

AWS credentials in prod come from the ECS task role (default credential chain). No access keys anywhere.
